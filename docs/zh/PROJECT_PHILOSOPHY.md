# CTX 项目理念

如果语言模型及其代理丢失了上下文，这就是你需要的工具。

CTX 建立在一个简单的想法之上：

- 结构化推理应该可以版本化
- 认知仓库应该能本地存在
- `.ctx` 格式必须可移植
- 用户应保持对数据与工作流的控制权

## 原则

### 1. Local-first 使用

CTX 必须能够在本地安装、运行并使用，而不依赖中心化服务。

### 2. 可修改与可扩展

CTX 应该可以被修改、适配与扩展。项目并不是要阻止 forks 或修改，而是要防止对作者身份、品牌和官方服务的错误占有。

### 3. 开放标准

`.ctx` 格式必须是开放且可移植的标准。认知仓库不应被锁进封闭平台。

### 4. 可商业化的软件

CTX 在项目许可下允许本地与 on-premise 商业使用。其核心业务是软件。

### 5. 未获许可不得提供竞争性服务

许可证限制的不是软件的使用或修改，而是在未获单独授权的情况下将 CTX 作为竞争性服务提供。

### 6. 品牌与官方方向受保护

CTX 这个名字、官方发行版与项目方向，仍应由项目持有人控制。

## 实际模型

CTX 寻求以下平衡：

- 对使用开放
- 对修改开放
- 在同一许可证下允许再分发
- 但防止对官方服务的商业性挪用

## CTX 希望促成的事情

- 本地认知仓库
- 真正的技术采用
- 扩展与集成
- self-hosted 部署
- 专业与商业化的 on-premise 使用

## CTX 想避免的事情

- forks 被包装成官方发行版
- 未获许可提供竞争性 SaaS
- `.ctx` 标准被第三方攫取

## 战略方向

CTX 不是要成为一个封闭工具。它应该成为认知版本化的开放基础，同时保持一个强势的官方项目、清晰的许可证，以及一致的技术方向。
