How the GitHub-native CTX demo is delivered.

CTX uses GitHub Codespaces for the runnable viewer and GitHub Pages for the static landing. Pages explains the demo. Codespaces runs it.

Back to docs Open in Codespaces

Why the split exists

GitHub Pages is static hosting. It cannot run the CTX Viewer backend or inspect a .ctx repository by itself. The runnable part therefore lives in a Codespace.

Canonical demo repository

The default demo dataset is examples/ctx/agent-session-continuity, chosen because it shows continuity across sessions instead of a one-shot graph.

Codespaces flow

  1. dotnet restore Ctx.sln runs on create.
  2. scripts/start-codespaces-demo.sh starts the viewer on 0.0.0.0:5271.
  3. The script sets CTX_VIEWER_DEFAULT_REPOSITORY_PATH to the tracked demo repo.
  4. Codespaces forwards port 5271 publicly.

Manual relaunch

bash scripts/start-codespaces-demo.sh

Logs are written to /tmp/ctx-viewer-codespaces.log.

Delivery model

  • GitHub Pages = static landing
  • GitHub Codespaces = live viewer
  • Local MCP = your machine plus your MCP-capable agent
  • tracked .ctx example = demo data

Local MCP setup

The static page can prepare copy-ready configuration for each agent, but the MCP server itself still runs locally through ctx-mcp.
